# 人物身份路由

仅在请求包含人物图、换人物意图或“恢复 Xinju”时读取。

## Skill 状态边界

- 本 Skill 的活动人物只保存在本目录的 `assets/ip/active-ip-four-view.png` 与 `references/character-ip.md`。
- `xinju-ip-illustrations-custom-lab` 等其他 Skill 拥有各自独立的活动人物；在一个 Skill 中替换人物，不会同步到另一个 Skill。
- 用户点名调用哪个 Skill，就只读取和改写该 Skill 的人物状态；不得跨目录借用另一 Skill 的活动人物。

1. 用户明确说“恢复 Xinju”或“切回 Xinju”时，恢复默认，不再判断同一请求中的其他图片。
2. 用户明确说“替换人物”“作为新 IP”“使用这个人物 IP”且提供人物图时，进入替换。真人照片的这类明确指令同时视为本人或授权使用确认，不重复询问。
3. 用户只上传照片或 IP、但没有身份替换意图时，它只是普通参考，不能替换活动人物。
4. 构图图、物件图、产品截图、风格图、历史配图和文章素材都不能触发替换。
5. 其他情况持续使用当前活动人物。

## 合格输入

- 只有一个明确人物，脸部与完整身体或主要服装、鞋型清楚可见。
- 多视图或四视图是稳定身份参考；单张清楚全身 IP 允许直接使用，但只可依据可见事实建档。
- 多人、头像、严重遮挡、低清或多个角色无法判断目标时，要求用户补图或明确目标。不得选择、推断或混合人物。

## 唯一活动身份

- 日常配图只输入 `assets/ip/active-ip-four-view.png`，并只读取当前 `references/character-ip.md`。
- 创建真人 IP 时，默认 Xinju 母板只锁共同骨架与渲染层级；替换完成后的日常生图不得再次同时输入默认 Xinju 母板。
- 当前人物档案不得残留与新人物冲突的 Xinju 发型、眼镜、服装、配色或性别化身份特征。
- 直接替换只改活动母板和人物档案；构图、物件、三种风格与 QA 规则不变。
- 替换状态持续生效，直到下一次明确替换或用户明确说“恢复 Xinju”。
- 不提供临时模式、人物版本库或“回退上一个人物”。唯一恢复入口是“恢复 Xinju”。
