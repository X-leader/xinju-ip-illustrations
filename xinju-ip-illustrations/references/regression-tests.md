# 回归测试集

本文件只在修改、审查或升级 Skill 时使用，不参与日常配图，也不作为生图案例输入。每次重要修改后，用相同题目检查是否出现能力退化；不要求每次都实际生成全部 12 张，可先做方案检查，再选择风险最高的风格生图。

## 固定测试题

1. **Workflow**：零散素材进入一个轮廓简单的日常处理物，输出清晰成稿。检查横向因果、主路径、中间尺度和核心处理物层级；不得退化成带多组仪表、面板、轨道和内部机构的复合机器。
2. **系统局部**：一组巨大透明管道只有中央接头漏水，活动人物精密修复。检查局部问题表达、接触关系、表情与留白。
3. **抽象判断**：它不是 ChatGPT 的替代品，而是嵌入软件系统里的智能判断函数。检查抽象概念能否变成一个物理隐喻，而不是 UI 或架构图。
4. **筛选动作**：巨大茶漏筛掉噪声，活动人物接住重点。检查巨大物件、平衡动作、信息层级和风格统一。

## 人物替换覆盖

1. **默认回归**：无人物图时，活动人物仍为 Xinju，原有方案展示、数字选风格并直接生图的流程不变。
2. **防误触发**：上传构图、产品截图或风格参考但未提出替换时，活动母板和人物档案均不得改写。
3. **真人转 IP**：明确授权的真人照片生成一致多视图母板；背景、姿势、摄影比例、光照与精确肤色不得进入活动 IP。母板要保留共同迷你荒诞骨架与照片中的身份锚点。
4. **已有 IP 直替**：上传清楚的现有 IP 并明确替换时，直接成为活动人物；其五官、比例、服装、配色和怪诞特征不得被改成 Xinju。
5. **单视图边界**：单张完整 IP 可以替换，但人物档案必须标记单视图限制，后续不得虚构未知结构。
6. **身份隔离**：创建真人 IP 时，默认 Xinju 母板只锁共同骨架与渲染层级，真人照片只锁身份与服装；结果不得复制 Xinju 的男性身份、发型、眼镜、白 T、蓝裤或配色。替换后的日常配图不得再次同时输入默认 Xinju 母板。
7. **眼睛自适应**：分别测试无眼镜和有眼镜人物。两者共享“短上眼睑＋单层深色眼核＋肤色负空间”，但眼距、眼角方向、眼核宽高比和眉眼距离来自各自参考；眼核中等偏小且清楚，不得变成针点、小豆点、动漫大眼、多层虹膜、明显眼白边框或反光高光。
8. **状态隔离与持续性**：在本 Skill 替换后，连续两次正文配图都读取同一活动人物；实验版或其他 Skill 的活动人物不随之改变，也不能反向覆盖本 Skill。
9. **动作压力测试**：替换后的角色分别执行拉拽、攀爬或悬挂、精细操作；检查唯一完整四肢、动作接触、服装体积、鞋型与五官稳定性。
10. **恢复默认**：用户明确“恢复 Xinju”后，活动母板和档案均恢复内置 Xinju；不提供回退上一个人物。

## 数字选择交互

1. 方案与三种风格展示后，分别测试单独回复 `1`、`2`、`3`：每个编号都必须同时采用当前方案与对应风格，并直接调用 image_gen；不得出现“请再确认方案”“请回复确认方案”或同义的第二次确认。
2. 回复 `1 和 3` 时，视为采用当前方案并分别生成两种风格的独立图片，不拼成一张。
3. 用户修改方案后，以最新修订方案为唯一待生成方案；收到编号立即生成最新方案，不得沿用旧版。
4. 没有待生成方案时收到孤立数字，或用户只说“确认”但没有唯一当前风格时，只询问其所指内容或要求选择编号，不擅自生图。

## 三种风格覆盖

- 手绘线稿重点检查：纯白背景、细至中等黑色手绘线；活动人物稳定保留肤色、1–2 个身份色和全部身份锚点。首稿仍以平坦哑光处理为目标，但人物身份稳定时的轻微 3D 明暗、发丝亮部或材质层次只能记为软偏差，不触发人物重绘。
- 平涂插画重点检查：人物与物件使用同一套几何色面，背景保持单一主色调并允许克制的中心提亮、柔和明暗过渡和轻微暗角，硬边投影有来源；背景不能强到抢夺主体或变成写实空间光照。
- 拼贴漫画重点检查：人物是真正的纸偶而不是线稿贴纸，背景连续，碎纸不过量。

## 评分表

每项按 0–2 分记录：0 为失败，1 为可用但不稳，2 为稳定通过。

1. 人物身份：比例与身形倾向、发型、眼距与眼角方向、眼核宽高比、可选眼镜、小鼻子、服装体积、鞋型与当前身份参考一致。
2. 风格统一：人物、物件和背景属于同一渲染语言。
3. 动作因果：移除活动人物后隐喻不再成立，表情与动作一致。
4. 构图尺度：符合 `composition-lock.md` 的中间尺度，无贴边或中央小图，顶部与底部都有连续安静背景带。
5. 文字准确：必须文字逐字正确、短而可读。
6. 信息与物件层级：第一眼先看到动作和因果；最多四类可见元素和一个决定性动作；默认一个轮廓简单的主物件，只保留决定性接触点和 1–3 个功能结构；没有把多组仪表、轨道、操纵杆、面板或内部机构包装成一个复合机器，辅助信息和机械纹路没有抢走主次。
7. 首稿与验收一致：普通横版与横版 Workflow 共用中央布局区域，尺寸只读取 `composition-lock.md`；构图锁位于内容锁之前。给出宽高关系不同的两组场景，检查能否保持自然比例安排进区域，而不把宽度和高度同时强行填满。首次 Prompt 不混入另一套成图或修正比例。
8. 软偏差不修正：测试一张宽度小于旧规则下限但动作与文字仍清楚的图、一张高度约 78% 但四周仍有连续留白且无裁切或明显压迫的图，以及一张人物有轻微 3D 发丝亮部但身份锚点稳定的手绘图；三者都必须直接采用初稿，不调用第二次 image_gen。不能用视觉重量或背景面积估算将其判为失败。
9. 修正次数上限：初稿同时存在真实贴边／裁切与必须文字错误时，把全部硬缺陷合并到一次修正生成，锁定人物现有身份、姿态与材质并只展示最终采用图片；修正版退化或仍有问题时回退，不进行第二次修正生成。
10. Workflow 外接范围：测试一个含输入、处理、输出、中文短标签、橙色箭头与动作提示的横版 Workflow。输入输出与标签必须整合进中央物件入口／出口或紧贴其轮廓，不得出现画布边缘外挂卡片、牌子或孤立提示符；全部元素就位后仍应保留连续四边白边和清楚的上下背景带，并优先一次生成通过。
11. 单物件复杂度：测试一句包含四项并列判断与一个输出动作的 Workflow。整图最多保留活动人物、一个简单核心物件、一个判断符号组和一个输出组；人物只做一个决定性动作。四项判断必须合并为一个紧凑符号组或同一表面上的短标注，主物件仍能用“一个轮廓＋三个以内功能点”概括；不得为每项建立独立仪表、轨道、面板或机械模块。
12. 纵向呼吸压力测试：分别检查人物站在巨大物件顶部、人物悬挂在节点结构下方、人物位于环形齿轮中央三种横版方案。预检必须把发梢、鞋底、投影、动作线和拼贴外缘计入最高与最低锚点；先减少纵向堆叠并改为低矮横向关系，再考虑整体缩放。成图顶部与底部都要保留连续背景带，同时主体不能退化成中央小图。
13. 修正证据：对比“箭头离近似布局线更近，但未贴画布边且清楚可读”与“箭头尖端被实际画布裁掉”两种结果；只有后者进入修正，且必须指出被裁掉的具体元素。按每张图记录 image_gen 调用数与触发原因，正常首稿应为 1 次，真实硬缺陷最多为 2 次；不以只展示最后一张代替调用次数检查。

前 6 项总分低于 9/12 分，或任一项为 0，视为画面回归；第 7–13 项不计入画面分，但必须通过。只根据重复出现的问题修改 Skill；不要因一次偶发差异新增普遍规则。
