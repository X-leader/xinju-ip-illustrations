# Xinju IP 配图 Skill

## 核心定位

为中文文章和短口播设计、生成静态配图，默认画幅为 16:9 横版；用户明确指定其他比例时，按该画幅原生构图。把正文或口播里的关键判断、流程、结构、状态或隐喻，变成一张清爽、怪诞、有创意、可读但不像说明书的解释图。

默认视觉主体是 Xinju；但 skill 同时只存在一个“活动人物 IP”。人物身份、比例、发型、眼镜、服装、表情与动作规则只读取 `references/character-ip.md`，日常身份图只读取 `assets/ip/active-ip-four-view.png`。新安装时活动人物就是 Xinju。

活动人物状态只属于本 Skill，不与 `xinju-ip-illustrations-custom-lab` 或其他 Skill 同步。用户点名本 Skill 时，只读取和改写本目录的人物母板与档案；需要知道当前人物时，可以直接询问“当前活动人物是谁”或“展示当前活动 IP”。

只有用户明确上传人物并表达“替换人物”“作为新 IP”“使用这个人物 IP”或同义身份意图，才进入替换流程；构图图、风格图、截图、物件图和历史配图都不能触发替换。真人照片只处理用户本人或已获授权人物。替换完成后，新母板与人物档案直接覆盖活动人物；不提供临时模式、版本列表或“回退上一个人物”。用户明确说“恢复 Xinju”时，恢复内置 Xinju 母板和默认档案。角色通过与巨大日常物件的尺度错位承担核心动作，并把身份结构转译为所选风格，不能直接继承身份图的柔和 3D 材质。

## 风格选择

支持三种模式；内容、IP 与构图规则共享，只有渲染语言不同：

- **手绘线稿**：选项一。纯白、极简黑色手绘细线；活动人物可见的脸、耳、颈部、手臂和手统一使用人物档案规定的单一浅暖桃肤色平坦哑光填充，头发、服装和鞋只保留 1–2 个身份色，画面再使用少量红橙蓝批注。肤色不做渐变、腮红、柔光或写实建模。兼容“原生手绘”旧称。
- **平涂插画**：选项二。单一主色场、几何平涂造型和硬边投影；背景允许克制的中心提亮、柔和明暗过渡与轻微暗角，以增强空间感，但不能抢过主体或变成写实场景光照。兼容“色场影构”“几何色场硬影”“几何扁平”或“硬边光影”。读取 `references/style-colorfield-shadow.md`。
- **拼贴漫画**：选项三。有色纸面、半调纸偶、手工裁切与中文批注；兼容“纸偶批注拼贴”“拼贴风格”“半调纸拼贴”或“纸偶”。读取 `references/style-paper-puppet-collage.md`。这里的“漫画”指单幅编辑式拼贴，不生成多格分镜或对白气泡。

用户一次指定多个风格时，为每种风格分别生成独立图片，不拼成一张。风格只改变材质、背景、线面和光影，不能改变核心判断、隐喻、角色动作、物件数量、中文标注或留白结构。

## 按阶段读取

- **人物路由阶段**：请求含上传人物图、换 IP 意图或恢复 Xinju 时，先读取 `references/character-routing.md`；处理真人转 IP 或现有 IP 替换时，再读取 `references/custom-character.md` 与 `references/character-profile-template.md`。
- **方案阶段**：读取 `references/composition-patterns.md` 与 `references/composition-lock.md`，确定隐喻、动作、结构和中间尺度。
- **生图阶段**：再读取 `references/character-ip.md`、`references/prompt-template.md` 与用户选定的单个风格文件；不要加载另外两种风格文件。
- **QA 阶段**：生成后才读取 `references/qa-checklist.md`；正常生图 Prompt 不复制 QA 条目。
- `assets/ip/active-ip-four-view.png` 是日常生图唯一身份参考，负责“是谁”。`assets/ip/xinju-ip-four-view.png` 仅用于默认初始化、真人转 IP 的共同结构参考和用户明确的“恢复 Xinju”，不得在自定义 IP 日常生图时同时输入。所选风格对应的 `assets/style/*-style-board.png` 只负责“怎么画”，不得决定主题、动作、物件或构图。
- `references/regression-tests.md` 只在修改或审查 Skill 时读取，不参与日常配图。

## 工作流

### 0. 人物替换路由

- 没有明确换人物意图：跳过，继续使用当前活动人物。
- 用户明确说“恢复 Xinju”或“切回 Xinju”：运行 `scripts/set_active_character.py --reset-xinju`，不再判断同一请求中的其他图片。
- 上传真人照片并明确要求替换：先生成标准人物母板，QA 通过后直接设为活动人物；不再次询问临时或默认。
- 上传清楚的已有 IP 并明确要求替换：不重设计人物，直接提取档案并设为活动人物。四视图或多视图优先；单张完整全身 IP 可以直接使用，但必须在档案中标记“单视图参考”，不得虚构未展示的发型、服装、鞋型或背面结构。
- 人物图多人、头像、严重遮挡或主体不清时，请用户补充合格图片，不能擅自选择、猜测或替换。

设置活动人物时，使用 `scripts/set_active_character.py` 同时写入活动母板和人物档案。该脚本只保留当前活动人物；原始真人照片、私人 IP、人物档案和测试结果不得加入开源资产、案例或回归测试。

人物替换请求只完成“人物母板生成／整理、人物 QA、写入活动状态”，不进入正文配图的方案与三种风格确认。替换完成后，后续新的正文配图请求才恢复正常的“方案 → 风格确认 → 生图”流程。

### 1. 消化正文或短口播

先读正文、短口播文稿、链接、Notion 页面、Markdown 文件或截图，提炼核心观点、认知转折、适合视觉解释的内容，以及不需要配图的部分。

不要平均配图。优先选择核心判断、断点、输入输出闭环、分流、前后对比、一鱼多吃、承接路径、常见坑和角色状态变化等“认知锚点”。

处理短口播时，先把口语表达压缩成一个可视化的核心判断或转折，不逐句机械配图。单句或短口播默认设计 1 张；只有存在两个独立认知锚点时才建议 2 张，通常不超过 3 张。默认仍输出静态配图，不自动拆成视频分镜或运动提示词，除非用户明确要求。

### 2. 第一阶段：方案说明与风格选择

任何新配图请求都先停在方案阶段，即使用户一开始就说“生成”或已经点名一种风格，也不要在这一阶段调用 image_gen。先读取 `references/plan-output-template.md`，严格使用其中固定的标题、九个字段、字段顺序、三种风格说明与结尾确认语。不得临时删除、改名或重排字段，也不得改成自由叙述；字段不适用时写“无”。固定的是说明模板，不是画面内容，每次仍须根据当前正文重新设计隐喻、动作、物件与构图。

正文默认 4–8 张；短文 1–3 张；单句或短口播默认 1 张，通常不超过 3 张；长文通常不超过 9 张。

多张配图按模板逐张输出，全部方案之后只提供一次风格选择。用户已点名风格时，将其标为“当前选择”，但仍列出全部三种供核对。未收到明确确认前停止，不生成图片。

有效确认需要能判断两件事：方案已通过、最终风格已确定，例如“确认，用手绘线稿”“方案可以，选拼贴漫画”。如果用户只说“确认”且前文已有唯一的当前选择，则沿用该选择；如果仍没有唯一风格，继续请用户选择，不擅自默认。

用户修改主题、隐喻、动作、构图、文字或风格时，先输出修订后的方案摘要并再次等待确认。只有用户在当前请求中明确要求“跳过确认直接生成”，才允许跳过本阶段。

### 3. 第二阶段：确认后单张生成

仅在用户已经确认配图方案和最终风格后，用内置 `image_gen` 每张单独生成，不把多张正文或短口播配图拼成一张。确认只授权生成已确认的方案；不要借此改变核心隐喻、动作、物件、标注或图片数量。

生成含人物的图片时，同时输入唯一活动身份参考 `assets/ip/active-ip-four-view.png` 与所选风格母板。身份参考只锁定人物结构；风格母板只锁定渲染语言，严禁复制母板的示例姿势、局部物件、排布或留白。使用 `references/prompt-template.md` 的精简模块组装 Prompt；平涂插画额外加入 `references/style-colorfield-shadow.md` 的人物平涂转译锁。

调用 image_gen 前先在内部完成一次“首稿构图预检”，不把预检过程展示给用户：先放完人物、主物件、输入输出、必须文字、箭头、动作线、人物头发与鞋底、投影和拼贴外缘，再以其中真正最左、最右、最高、最低的元素确定完整视觉组边界；指定人物、巨大主物件和必须文字分别落在哪个区域，并确认所有元素都位于同一个安全框内。16:9 横版先减少纵向堆叠，优先使用横向展开、低矮团块、浅对角线或环形关系；可选批注若会成为新的最外侧锚点，必须删掉或内移。首次 Prompt 只使用 `composition-lock.md` 的单一保守生成目标，不同时塞入多个允许区间、视觉重量和空白比例。普通横版首稿瞄准约 74% 宽、60% 高；横版 Workflow 首稿瞄准约 76% 宽、60% 高，纵向大致位于 y=20%–80%。这里的较小数值是抵消生图模型自然放大倾向的“生成偏置”，不是最终验收标准；最终仍按中间尺度 QA 规则判断。

每张图必须包含：

- 使用方案中已确认的画幅，默认 16:9 横版；把人物、主物件、箭头、输出、批注、人物头发与鞋底、投影、动作线和拼贴外缘收拢为一个完整视觉组，并严格执行 `references/composition-lock.md`。该文件是三种风格唯一有效的构图占比来源
- 完整视觉组必须围绕画面中心收拢并形成明确的中央视觉重心；留白分布在上下左右四周，顶部与底部都保留连续安静背景带，不能偏压单侧，也不能缩成漂浮在中央的小图
- Workflow 只使用 `references/composition-lock.md` 中的横版 Workflow 例外；输入、输出、标签和橙色动作提示优先嵌入中央处理物或紧贴其轮廓，禁止在安全框外另挂卡片、牌子或孤立提示符；竖版改用自上而下、S 形或错层纵向流程
- 少量红色、橙色、蓝色或黑色中文手写批注
- 当前活动迷你 IP 作为核心动作主体
- 手绘线稿中的活动人物是“黑白线稿＋单一浅暖肤色＋1–2 个局部身份色”，不是全身彩色人物：脸、耳、颈部、手臂和手必须完整填充人物档案规定的单一浅暖桃肤色并保留黑色轮廓；头发、服装、眼镜和鞋按当前人物档案简化。肤色只作为平坦哑光色面，不得出现纸白漏填、腮红、渐变、空气感皮肤、柔和 3D 明暗、高光或写实材质
- 默认只使用一个巨大核心物件制造怪诞感；“巨大”只表示它相对迷你人物巨大，不表示它要相对画布铺满。只有第二个物件承担不可替代的输入、输出、阻力或连接关系时才保留。IP 承担核心动作，但不能压过主物件和核心结构
- 物件执行 `references/composition-patterns.md` 的“可读细节预算”：保持一个可识别外轮廓和与动作直接相关的接触点，但不能把主物件压成只有文字才能识别的方盒、圆片或按钮集合。普通概念物件通常保留 2–4 处有效细节；产品、工作台、节点编辑器和系统局部允许 4–6 处有效细节。有效细节只用于物件身份、人物操作和因果叙事，并尽量各保留至少一处；可额外保留一组克制的材质或结构特征。禁止把多组仪表、轨道、操纵杆、面板、管线或内部机构包装成“一个物件”，也不能用装饰螺丝、重复接口和密集纹路填充复杂度。流程节点、内部小符号、箭头、投影和批注不能混为核心物件，但仍计入整体视觉密度
- 每张图执行“四元素预算＋一个动作锁”：最多使用活动人物、一个核心物件、一个紧凑输入或状态组，以及一个紧凑输出组或必要辅助物；人物只执行一个造成核心变化的动作。超量时按 `references/composition-patterns.md` 的删除阶梯合并、删除或更换隐喻，不能把多个部件藏进一台复合机器绕过预算
- 人体结构必须完整且唯一：除被物件合理遮挡外，只能有一个头、一个躯干、两条手臂、两只手、两条腿和两只脚；手臂、手掌、腿脚与关节必须连续连接，禁止多手、多臂、多腿、重复肢体或悬空肢体
- 与动作因果一致的夸张表情和身体语言；只要脸部可见，就必须保留清晰可读的嘴形，不得因角色较小或画面复杂而省略
- 按 `references/composition-patterns.md` 执行动作、表情、人物朝向、接触关系和构图骨架去重；不能默认套用“侧面推巨大物件＋眯眼咬牙＋横向输入输出”
- 禁止 PPT、商业插画、幼稚可爱、复杂架构与左上角类型标题

背景、线面、材质与阴影按所选风格 reference 执行。生成 Prompt 时，在画幅与参考图职责之后立即原样加入 `references/composition-lock.md` 的生图构图锁定块，使构图成为最高优先级；随后依次写内容锁、人物身份锁、渲染锁和最终文字检查。首次 Prompt 不在其他段落重复构图数字。平涂插画加入 `style-colorfield-shadow.md` 的“主色场与空间层次锁”，允许背景出现克制的中心提亮、柔和明暗过渡和轻微暗角；只在背景光影强到抢夺主体、破坏文字可读性或形成写实场景时修正。新增风格优先单次生成；不要先生成原生图再做风格转换，除非用户明确要求两阶段或单次生成持续发生内容漂移。

每张图只讲一个核心结构。每次从当前正文或短口播重新发明奇怪但成立的隐喻，不复刻历史图片的具体构图。中文文字执行 `references/prompt-template.md` 的文字锁：关键文字必须逐字准确；可选文字在无法保证正确时宁可省略，不能生成近似错字。

### 4. 检查与迭代

按 `references/qa-checklist.md` 和所选风格 reference 静默检查。先保存初稿并锁定它最强的 2–3 项，再区分硬缺陷与软偏差。没有硬缺陷时直接采用初稿，不因“可能还能更好”惯性生成第二版。

存在真实硬缺陷时仍必须修正，包括：主体贴边、裁切，顶部或底部连续背景带被外延元素打断并形成明显空间压迫，视觉组明显偏离中心，必须中文缺失或错字，以及身份、人体、语义、动作或物件错误。构图百分比只是诊断参考，不能单独触发修正：即使完整视觉组的高度或宽度略超参考区间，只要四周仍有连续留白、没有贴边裁切、没有明显压迫或失衡、动作与文字仍清楚，就直接采用初稿。

人物材质也不能因“比目标略立体”单独触发修正。只在发型轮廓、脸部结构、眼镜、头身比、服装、鞋型、身份色等身份锚点发生明显漂移时，才修正人物；轻微 3D 层次、发丝亮部、皮肤明暗或材质细节属于软偏差。构图修正不得顺便要求重绘人物材质。

确认存在硬缺陷后，先一次性汇总初稿中全部已确认的硬缺陷，再发起且只发起 **一次** 定向修正生成；同一张图最多调用 image_gen 两次，即一次初稿加一次修正，不得按“先修尺度、再修文字、再修人物”的方式连续生成多个修正版。修正 Prompt 同时列出全部硬缺陷，并把初稿最强的 2–3 项写成禁止改变项；软偏差不得混入修正清单。

修正后重新 QA：只有在硬缺陷整体减少、锁定优势未退化且没有新增更严重硬缺陷时，才采用修正版；否则回退初稿并停止。修正版仍有问题时，不进行第二次修正生成；除非用户明确要求新的独立尝试，才开始新的生成轮次。

只有留白问题已经表现为贴边、裁切、上下连续背景带断裂并形成明显压迫、明显偏心或小到影响阅读时，才进入构图修正。先读取 `references/composition-lock.md` 的“中间尺度构图规则”，量化完整视觉组的外接范围和四边留白，再把当前估算值、缩放方向与一个标称目标写入唯一一次定向修图 Prompt。普通横版修正到约 80% 宽、64% 高，横版 Workflow 修正到约 83% 宽、64% 高；不要把整套允许区间再次塞入修正 Prompt。缩放必须作用于人物、物件、箭头、文字、投影和全部外延元素组成的完整视觉组，内部相对坐标不变，并明确锁定人物现有身份、姿态与材质，不得重绘人物。修正版若从过满跳成中央小图，按修正失败处理并回退最佳版本。

### 5. 保存交付
